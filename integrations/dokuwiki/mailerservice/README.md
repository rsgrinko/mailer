# Плагин DokuWiki — отправка почты через сервис рассылки

Перехватывает всю почту DokuWiki (подписки на страницы, регистрация, сброс пароля,
уведомления плагинов) и отдаёт её сервису рассылки по HTTP API вместо `mail()`.

Письмо собирает сама вики — плагин берёт уже готовый MIME (`Mailer::dump()`) и отправляет
его полем `raw`. Поэтому шаблоны писем, вложения, кодировки и заголовки DokuWiki остаются
нетронутыми, а сервис добавляет очередь, повторы, DKIM, историю и панель.

## Требования

- DokuWiki 2018-04 «Greebo» и новее, PHP 7.4+.
- Работающий сервис рассылки и API-ключ проекта.

## Установка

Скопировать каталог `mailerservice` в `lib/plugins/` вики:

```bash
cp -r integrations/dokuwiki/mailerservice /var/www/dokuwiki/lib/plugins/
chown -R www-data:www-data /var/www/dokuwiki/lib/plugins/mailerservice
```

Через менеджер расширений (Установка вручную → загрузить архив) — так же, если запаковать
каталог в zip: имя каталога внутри архива должно остаться `mailerservice`.

## Настройка

Ключ проекта выдаётся на стороне сервиса:

```bash
php bin/mailer key:create dokuwiki
```

Дальше в вики: **Управление → Настройки** (`?do=admin&page=config`), раздел
«Плагин mailerservice»:

| Настройка   | Что означает                                                              |
|-------------|---------------------------------------------------------------------------|
| `url`       | адрес сервиса, например `http://mail.internal` (без `/api/v1`)            |
| `apikey`    | API-ключ проекта                                                          |
| `mode`      | `queue` — отдать письмо в очередь и не ждать; `sync` — дождаться отправки |
| `transport` | имя транспорта, если нужен конкретный; пусто — транспорт по умолчанию     |
| `tag`       | метка писем в панели сервиса, по умолчанию `dokuwiki`                     |
| `timeout`   | таймаут запроса к сервису, секунд                                         |
| `fallback`  | если сервис недоступен — отправить письмо штатными средствами DokuWiki    |

Пока не заполнены `url` и `apikey`, плагин не вмешивается: почта уходит как раньше.

Отправитель берётся из настройки вики `mailfrom` — адрес должен быть разрешён транспорту
сервиса, иначе SMTP-сервер отклонит письмо (`553 Sender address rejected`).

## Проверка

**Управление → Сервис рассылки** (`?do=admin&page=mailerservice`):

- текущие настройки одним списком;
- «Проверить» — запрос `/api/v1/health`: база, очередь, воркер;
- тестовое письмо — уходит обычным путём DokuWiki, то есть проверяет всю цепочку
  вместе с плагином.

Отправленные письма видны в панели сервиса с меткой `dokuwiki`; в `meta` попадают название
вики и логин пользователя, от чьего действия ушло письмо.

## Режим `sync`

По умолчанию (`queue`) вики получает ответ сразу после постановки письма в очередь —
страница не ждёт SMTP. Режим `sync` заставляет сервис отправить письмо немедленно и вернуть
результат: DokuWiki покажет честный «письмо отправлено/не отправлено», но действие
пользователя будет ждать SMTP-сервер. Для вики с подписками разумнее `queue`.

В этом режиме письмо, которое сервис принял, но не смог отправить, — не то же самое,
что непринятое: оно есть в панели со статусом `failed`, и его можно повторить оттуда.
В журнал вики попадает причина от почтового сервера, а не «сервис ответил кодом 502».

## Что делать, если сервис лёг

При `fallback = вкл` (по умолчанию) плагин отдаёт письмо обычной отправке DokuWiki, а ошибку
пишет в журнал (`data/log/error/`). Выключенный `fallback` означает «либо через сервис, либо
никак» — DokuWiki сообщит об ошибке отправки.

## Как устроено

Плагин подписан на событие `MAIL_MESSAGE_SEND` (BEFORE):

1. `action.php` — берёт `Mailer::dump()`, отдаёт хелперу, при успехе ставит
   `success = true` и отменяет штатную отправку (`preventDefault`, `stopPropagation`).
2. `helper.php` — клиент API: `POST /api/v1/messages` с полем `raw`, разбор ошибок,
   `GET /api/v1/health`. Запросы идут через `DokuHTTPClient`, то есть с учётом прокси вики.
3. `admin.php` — страница администратора.

# sendmail-шим для чужого сервера

Подменяет системный `sendmail` на любом сервере и уводит всю его почту в наш
сервис по HTTP API. Приложение править не нужно: `mail()` в PHP, `sendmail` из
скриптов, письма из CMS и cron-задач начинают уходить через сервис как были.

В самом проекте уже есть `bin/mailer-sendmail`, но он кладёт письмо прямо в базу
и потому работает только на сервере с сервисом. Эти два скрипта — для всех
остальных: им нужен только сетевой доступ к сервису и ключ проекта.

| Файл | Кому |
|------|------|
| `mailer-sendmail` | POSIX-shell плюс `curl`. Ставится куда угодно, PHP не нужен |
| `mailer-sendmail.php` | Там, где PHP уже есть: хостинги с WordPress, Bitrix, самописью |
| `mailer-sendmail.conf.example` | Образец настроек, общий для обоих |

## Установка

1. Заведите на сервисе ключ под этот сервер — так письма будут видны отдельно
   и лимиты будут свои:

   ```
   php bin/mailer key:create shop-server
   ```

2. Положите скрипт и сделайте исполняемым:

   ```
   cp mailer-sendmail /usr/local/bin/mailer-sendmail
   chmod +x /usr/local/bin/mailer-sendmail
   ```

   Вариант на PHP ставится так же, только файл `mailer-sendmail.php`.

3. Заполните настройки и закройте файл от посторонних — в нём ключ:

   ```
   cp mailer-sendmail.conf.example /etc/mailer-sendmail.conf
   chown root:www-data /etc/mailer-sendmail.conf
   chmod 640 /etc/mailer-sendmail.conf
   ```

4. Скажите приложению слать через него.

   **PHP** (`php.ini`, обычно `/etc/php/8.2/fpm/php.ini`), после правки —
   перезапуск php-fpm:

   ```
   sendmail_path = /usr/local/bin/mailer-sendmail -t -i
   ```

   **Всё остальное на сервере** — подменить системный бинарник. Сначала уберите
   в сторону настоящий, чтобы можно было вернуть как было:

   ```
   mv /usr/sbin/sendmail /usr/sbin/sendmail.original
   ln -s /usr/local/bin/mailer-sendmail /usr/sbin/sendmail
   ```

   Так же подменяются `/usr/lib/sendmail` и `/usr/bin/mail`, если приложения
   зовут их напрямую.

## Проверка

```
printf 'Subject: Проверка шима\r\nFrom: robot@example.ru\r\nTo: you@example.ru\r\n\r\nПисьмо через сервис\r\n' \
    | /usr/local/bin/mailer-sendmail -t -i -frobot@example.ru
echo "код выхода: $?"
```

Ноль — письмо принято, ищите его в панели в разделе «Письма». Ненулевой код и
причина печатаются в stderr; если задали `MAILER_LOG`, там же будет запись.

## Коды выхода

Обычные для sendmail, поэтому Postfix, exim и скрипты понимают их без переводчика:

| Код | Что случилось |
|-----|----------------|
| 0   | письмо принято сервисом |
| 64  | ошибка в аргументах или пустой ввод |
| 65  | сервис не принял письмо: не прошло проверку (кривой адрес, пустое тело) |
| 75  | временная ошибка: сеть, таймаут, сервис недоступен или ответил 5xx |
| 77  | ключ не подошёл или отозван |
| 78  | шим не настроен: нет `MAILER_URL` или `MAILER_KEY` |

**Своей очереди у шима нет.** Недоступен сервис — письмо не принято, код 75.
Для писем из Postfix или exim это правильное поведение: они повторят сами. А вот
`mail()` в PHP повторять некому, поэтому при долгом простое сервиса такие письма
теряются — если это важно, отправляйте из приложения через SDK или API, там
ошибку видно сразу.

## Что уходит сервису

Письмо отдаётся целиком, как его собрало приложение (`raw`), плюс конверт:
отправитель из `-f` и получатели из аргументов, если они переданы. Сервис сам
разберёт заголовки, темы, вложения и получателей из `To`/`Cc`. Дополнительно в
`meta` уходит имя сервера-отправителя — в карточке письма видно, откуда оно.

Проверка адресов, стоп-лист, лимиты проекта, повторы и вебхуки работают ровно
так же, как для писем из API: шим — это просто ещё один способ их туда положить.

# Эксплуатация

## Веб-панель

Панель открывается по адресу `/ui/` (корень сайта туда же и уводит) и показывает всё,
что происходит в сервисе. Вход — по логину и паролю, см. «Пользователи панели» ниже.
Вёрстка рассчитана и на телефон: меню прячется под кнопку, списки показываются карточками.

| Раздел | Что там |
|--------|---------|
| Обзор | очередь, отправленные и неудачные за сегодня, график за две недели, состояние воркера, последние события и ошибки |
| Письма | список с фильтрами (статус, проект, транспорт, источник, метка, поиск, даты), массовые действия |
| Карточка письма | заголовки, HTML-превью, текст, письмо целиком, вложения, история попыток, вебхуки; кнопки «отправить сейчас», «вернуть в очередь», «отменить», «удалить», «написать похожее», «скачать .eml» |
| Написать | ручная отправка письма, в том числе по шаблону |
| Транспорты | создание и правка, проверка связи, включение и выключение, выбор основного |
| Проекты | ключи API, лимиты, вебхуки, отправитель по умолчанию, перевыпуск ключа |
| Шаблоны | правка и предпросмотр с подстановкой переменных |
| Вебхуки | очередь и история доставки, ручной повтор |
| Пользователи | те, кто может входить в панель: добавление, смена пароля, отключение, удаление |
| Логи | просмотр файлов из `var/log` |
| Состояние | база, миграции, счётчики лимитов, служебные значения, версия PHP, кнопки обслуживания |

Все списки постраничные: письма, вебхуки, проекты, транспорты, шаблоны и пользователи.
Сколько строк показывать на странице, задаёт `UI_PER_PAGE` в `.env` (по умолчанию 30);
номер страницы живёт в адресе (`?page=2`) и не сбрасывает выбранные фильтры.

Действия из панели можно отключить одной настройкой: `UI_ALLOW_ACTIONS=false` в `.env`.

## Пользователи панели

Вход по логину и паролю. Пользователей может быть сколько угодно, права у всех одинаковые:
вошедший может всё, включая управление другими пользователями. Требование к паролю одно —
не короче 6 символов; в базе хранится только хеш.

```
php bin/mailer user:create ivan               завести (пароль сгенерируется и покажется)
php bin/mailer user:create ivan --password=... --name="Иван"
php bin/mailer user:list                      кто заведён и когда входил
php bin/mailer user:password ivan             сменить пароль
php bin/mailer user:delete ivan [--force]     удалить
```

Пока в базе нет ни одного пользователя, панель открывает страницу первого запуска
`/ui/setup` и предлагает завести себя. Как только пользователь появился, страница закрыта.

Полезно знать:

- сессия живёт в куке `mailer_panel` (`HttpOnly`, `SameSite=Lax`); после
  `UI_SESSION_LIFETIME` секунд без активности (по умолчанию 12 часов) пароль спросят заново;
- после 10 неудачных попыток вход с этого адреса блокируется на 15 минут — счётчик лежит
  в таблице `counters` под ключом `login:<адрес>`, сбросить можно из раздела «Состояние»;
- отключённый пользователь теряет доступ сразу, даже если у него была открыта панель;
- последнего активного пользователя нельзя отключить или удалить, себя — тоже
  (в консоли ограничение снимает `--force`);
- если панель и так закрыта basic auth на nginx, свою авторизацию можно выключить:
  `UI_AUTH=false` в `.env`.

## Команды

```
php bin/mailer help              полный список
php bin/mailer status            общее состояние сервиса
php bin/mailer queue:status      что сейчас в очереди и последние ошибки
php bin/mailer worker            воркер (демоном)
php bin/mailer worker --once     один проход (для cron)
php bin/mailer worker:restart    попросить работающий воркер перезапуститься
php bin/mailer smtpd             локальный SMTP-релей
php bin/mailer route:list        какие адреса обслуживает сервис
```

## Перезапуск воркера

Воркер держит в памяти настройки и подключения, поэтому после правки транспорта или `.env`
его полезно перезапустить. Делается это без доступа к серверу: **Состояние → Перезапустить
воркер** в панели или `php bin/mailer worker:restart` в консоли.

Команда не убивает процесс, а оставляет пометку в таблице `settings`. Воркер видит её на
следующем круге (до `QUEUE_SLEEP` секунд), дописывает текущую пачку писем и выходит —
письма при этом не теряются. Дальше его поднимает systemd (`Restart=always` в
`deploy/mailer-worker.service`); если воркер запущен руками, запустить его нужно самому.

Понять, что перезапуск случился, можно на той же странице: у воркера сменится
идентификатор процесса, а в логе появятся строки «Запрошен перезапуск» и «Воркер запущен».

Очередь:

```
php bin/mailer queue:retry <id>          повторить письмо
php bin/mailer queue:retry --failed      повторить все неудачные
php bin/mailer queue:cancel <id>         отменить письмо
php bin/mailer queue:purge --status=sent --days=30
php bin/mailer webhook:process           разослать накопившиеся вебхуки
```

Проекты и ключи:

```
php bin/mailer key:create my-site --limit-day=5000 --webhook=https://example.com/hook
php bin/mailer key:list
php bin/mailer key:regenerate my-site
php bin/mailer key:revoke my-site
```

Транспорты:

```
php bin/mailer transport:list
php bin/mailer transport:test yandex
php bin/mailer transport:default yandex
php bin/mailer transport:add backup --type=smtp --host=... --user=... --password=...
```

Отправка:

```
php bin/mailer send:test user@example.com
php bin/mailer send --to=user@example.com --subject=Тема --text=Текст --sync
```

## Как сервис повторяет отправку

Ошибки делятся на две группы:

- **временные** — сеть недоступна, сервер ответил кодом 4xx, превышен суточный лимит
  транспорта. Письмо возвращается в очередь: следующая попытка через 1 минуту, затем 5, 15,
  60 и 180 минут (настраивается в `config/config.php`, ключ `queue.backoff`);
- **окончательные** — сервер ответил 5xx, отказался принимать адрес, не прошла авторизация.
  Письмо сразу помечается неудачным.

По умолчанию делается до пяти попыток (`QUEUE_MAX_ATTEMPTS`). Ручной повтор из панели или
командой добавляет письму новые попытки.

Если воркера убили посреди отправки, письмо остаётся в статусе `sending`. Через 15 минут
(`QUEUE_STUCK_AFTER`) воркер сам вернёт его в очередь; то же делает кнопка
**Состояние → Вернуть зависшие письма**.

## Лимиты

- у проекта — максимум писем в час и в сутки (проверяются при приёме, ответ 429);
- у транспорта — максимум писем в сутки (при превышении письмо откладывается, а не теряется).

Счётчики видны в панели на странице «Состояние», там же их можно сбросить.

## Логи

Пишутся в `var/log/mailer-ГГГГ-ММ-ДД.log`, читаются в панели в разделе «Логи».
Уровень задаётся `LOG_LEVEL` (`debug`, `info`, `warning`, `error`).

Чтобы посмотреть переписку с почтовым сервером при разборе проблем, включите
`LOG_SMTP=true` — в лог попадут все команды и ответы SMTP. В обычной работе это лишний шум.

## Разбор частых проблем

**Письма стоят в очереди и не уходят.** Не запущен воркер: `systemctl status mailer-worker`
или `php bin/mailer status` — там видно, когда воркер отзывался в последний раз.

**Ошибка «535 Authentication failed» у Яндекса.** Нужен пароль приложения, а не пароль от
аккаунта; в настройках почты должен быть разрешён доступ по SMTP. Проверить:
`php bin/mailer transport:test yandex`.

**Письма уходят в спам.** Проверьте SPF и DKIM домена отправителя. При отправке через SMTP
Яндекса подпись ставит сам Яндекс — достаточно правильных DNS-записей. При отправке через
sendmail включите DKIM в настройках транспорта.

**«Не удалось расшифровать значение: неверный APP_KEY?»** Ключ в `.env` изменился после того,
как пароли попали в базу. Верните прежний ключ или задайте пароли транспортов заново.

**Панель говорит «APP_KEY не задан».** Пароли лежат в базе открытым текстом. Сгенерируйте
ключ (`php bin/mailer app:key`), впишите в `.env` и пересохраните транспорты.

**Не проходит проверка сертификата SMTP.** В настройках транспорта снимите галку
«Проверять сертификат сервера» — но лучше сначала разобраться с сертификатами на сервере.

## Чистка

Отправленные письма хранятся 30 дней (`QUEUE_KEEP_SENT_DAYS`), дальше их можно удалять:

```
php bin/mailer queue:purge --status=sent --days=30
php bin/mailer queue:purge --status=failed --days=90
```

Вместе с письмом удаляются его история и файлы вложений из `var/spool`.

# Транспорты: как устроены и как добавить новый

Транспорт — это способ доставки письма наружу. Очередь, лимиты, стоп-лист, повторы,
вебхуки и панель к нему не привязаны: они работают одинаково, чем бы письмо ни
уходило. Поэтому новый транспорт — это один класс плюс несколько строк в местах,
где его нужно показать и настроить.

Что есть сейчас: `smtp`, `sendmail`, `log` (складывает `.eml` в файлы), `null`
(отбрасывает), `failover` (цепочка: пробовать по очереди) и `roundrobin`
(чередовать по кругу).

## Как это устроено

```
Sender -> TransportFactory::fromRow(строка из transports) -> TransportInterface::send()
```

- `Mailer\Transport\TransportInterface` — четыре метода: `send()`, `name()`, `type()`,
  `close()` и `test()`.
- `Mailer\Transport\BaseTransport` — общая часть: хранит настройки, отдаёт их через
  `setting()`, собирает MIME методом `render()` (там же DKIM-подпись и подмена
  отправителя по `force_from`). От него и наследуются все транспорты.
- `Mailer\Transport\TransportException` — ошибки. Разница принципиальная:
  `temporary()` — письмо вернётся в очередь и уйдёт позже, `permanent()` — сразу
  `failed`, повторять бессмысленно. Промах здесь стоит либо потерянных писем, либо
  бесконечных повторов в ящик, которого нет.

Настройки транспорта лежат в базе JSON-ом (`transports.settings`). Значения с именами
из `TransportRepository::SECRET_KEYS` (`password`, `api_key`, `secret_key`, `token`)
шифруются автоматически — назовите ключ провайдера одним из них, и он не окажется
в базе открытым.

## Что нужно сделать

Пример: транспорт `example` — отправка через HTTP API стороннего провайдера.

### 1. Класс транспорта

`src/Transport/ExampleTransport.php`:

```php
final class ExampleTransport extends BaseTransport
{
    public function type(): string
    {
        return 'example';
    }

    public function send(Message $message): string
    {
        $key = (string) $this->setting('api_key', '');

        if ($key === '') {
            // Ключа не будет и через час — это не «повторить позже»
            throw TransportException::permanent('Не задан ключ API транспорта «' . $this->name . '»');
        }

        // render() соберёт письмо целиком: заголовки, тела, вложения, DKIM
        $mime = $this->render($message);

        [$code, $body] = $this->post($key, $mime);

        if ($code >= 200 && $code < 300) {
            return 'Принято провайдером: ' . $body;
        }

        // 4xx — что-то не так с письмом, 5xx и обрывы — попробуем позже
        throw $code >= 400 && $code < 500
            ? TransportException::permanent('Провайдер отказал (' . $code . '): ' . $body)
            : TransportException::temporary('Провайдер недоступен (' . $code . '): ' . $body);
    }

    public function test(): string
    {
        // Зовётся кнопкой «проверить связь» и командой transport:test.
        // Ничего не отправляем — только проверяем доступ
        return 'Ключ принят, отправлять можно';
    }
}
```

Сеть — потоками (`stream_socket_client`, `file_get_contents` с контекстом) или `curl`,
если он есть: в проекте нет composer и внешних библиотек, HTTP-клиента писать самому.
Смотрите, как это сделано в `Webhook\WebhookSender` — там оба варианта.

### 2. Фабрика

`src/Transport/TransportFactory::fromRow()` — добавить ветку в `match`:

```php
'example' => new ExampleTransport($name, $settings),
```

### 3. Список типов

`src/Repository/TransportRepository::TYPES` — добавить `'example'`. Без этого
репозиторий не сохранит транспорт: тип проверяется при записи.

### 4. Форма в панели

`src/Ui/views/transport_form.php`:
- пункт в списке типов (`'example' => 'Example — отправка через API провайдера'`);
- блок полей для этого типа (по образцу блоков SMTP и sendmail);
- строка в сводке внизу файла, чтобы в карточке было видно, куда транспорт настроен.

`src/Ui/Controllers/TransportsController::save()` — ветка в `match ($type)`: какие поля
формы попадают в настройки.

### 5. Консоль

`src/Console/Commands/TransportAddCommand` — ветка по типу и разбор своих `--опций`,
чтобы транспорт можно было завести без панели.

### 6. Тесты

`tests/TransportTest.php` — отправка, ошибки и сборка из строки базы. Наружу ходить
нельзя: поднимайте заглушку отдельным процессом, как это делают `tests/smtp-stub.php`
и `tests/webhook-stub.php`, либо подменяйте бинарник, как в тесте sendmail.
Обязательно проверьте, что временная ошибка помечена временной, а постоянная —
постоянной: от этого зависит, попадёт письмо в повтор или сразу в «не отправлено».

### 7. Документация

Строка в `docs/OPERATIONS.md` и в списке типов в `CLAUDE.md`.

## О чём легко забыть

- **`close()`** нужен только транспортам, которые держат соединение (как SMTP). Держите
  сессию — закройте её здесь, воркер зовёт `close()` на опустевшей очереди.
- **`test()`** должен именно проверять доступ, а не отправлять письмо: его дёргают
  кнопкой в панели, в том числе на боевых транспортах.
- **Размер письма.** У провайдеров свои пределы на размер запроса; лучше проверить
  заранее и ответить понятной постоянной ошибкой, чем получить обрезанный ответ.
- **Секреты.** Имя настройки — из `SECRET_KEYS`, иначе ключ ляжет в базу открытым и
  будет виден в карточке транспорта.
- **Ответ `send()`** попадает в историю письма и в карточку. Пишите туда идентификатор
  письма у провайдера — по нему потом ищут, что случилось на той стороне.

## Что имеет смысл добавить

По убыванию пользы для этого сервиса:

| Транспорт | Зачем |
|-----------|-------|
| **Yandex Cloud Postbox** | То же облако, где уже живёт почта; API совместим с Amazon SES, лимиты выше, чем у обычного ящика Яндекса, и не рвётся сессия на `MAIL FROM` |
| **Amazon SES** | Дешёвая массовая рассылка, хорошая репутация IP. Подпись SigV4 считается через `hash_hmac`, зависимостей не нужно |
| **Mailgun / Postmark / SendGrid** | Простой HTTP с ключом в заголовке, готовая аналитика и отказы на их стороне; Postmark заметно лучше по доставляемости транзакционных писем |
| **Unisender / Sendsay / DashaMail** | Российские провайдеры: оплата в рублях, поддержка по-русски, меньше вопросов с 152-ФЗ |
| **Microsoft Graph (Office 365)** | Корпоративная почта без SMTP: во многих организациях SMTP AUTH выключен политикой, а Graph разрешён |
| **Gmail API** | То же самое для Google Workspace |
| **`pipe`** | Отдавать письмо произвольной команде (не только sendmail): удобно для интеграции с чужими скриптами и для отладки |
| **`weighted`** | Развитие `roundrobin`: раскладывать письма по транспортам в заданной пропорции — например, 80% через основной, 20% через запасной для прогрева домена |
| **`throttle`** | Обёртка над другим транспортом с ограничением скорости (писем в минуту) — у многих провайдеров лимит именно на темп, а не на сутки |

Первым разумно делать **Yandex Cloud Postbox или Amazon SES** — это один и тот же код
(SES-совместимый API), закрывает главную сегодняшнюю боль с лимитами почтового ящика
и не требует ничего, кроме `hash_hmac` и потоков.

Из составных полезнее всего **`throttle`**: сейчас при большой очереди сервис упирается
в темп провайдера и получает временные ошибки, а с ним письма просто уходят ровнее.

# HTTP API

Базовый адрес: `/api/v1`. Формат запросов и ответов — JSON в UTF-8.

Машиночитаемое описание — `docs/openapi.yaml` (OpenAPI 3.0): его понимают Swagger UI,
Postman, Insomnia и генераторы клиентов.

## Авторизация

Каждый запрос (кроме `/health`) требует ключ проекта:

```
Authorization: Bearer mlr_xxxxxxxx_xxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Для совместимости понимается и заголовок `X-Api-Key`.

Ключ выдаётся при создании проекта:

```bash
php bin/mailer key:create my-site
```

или в панели: **Проекты → Создать проект**. Полностью ключ показывается один раз — в базе
хранится только его хеш.

## Отправка письма

```
POST /api/v1/messages
```

Минимальный запрос:

```json
{
  "to": "user@example.com",
  "subject": "Заказ №1024 оформлен",
  "text": "Спасибо за заказ!"
}
```

Полный список полей:

| Поле | Тип | Описание |
|------|-----|----------|
| `to` | строка или массив | получатели; обязательное поле |
| `cc`, `bcc` | строка или массив | копии и скрытые копии |
| `from` | строка или объект | отправитель; если не указан — берётся из проекта или транспорта |
| `reply_to` | строка | адрес для ответа |
| `subject` | строка | тема письма |
| `text` | строка | текстовая версия |
| `html` | строка | HTML-версия (текстовая создастся сама, если её нет) |
| `template` | строка | имя шаблона из сервиса |
| `template_data` | объект | переменные шаблона |
| `attachments` | массив | вложения, см. ниже |
| `headers` | объект | дополнительные заголовки письма |
| `tag` | строка | метка для поиска в панели |
| `meta` | объект | произвольные данные, вернутся в вебхуке |
| `transport` | строка | имя транспорта, если нужен конкретный |
| `priority` | число | меньше — раньше отправится; по умолчанию 100 |
| `send_at` | строка | отложенная отправка: `2026-01-01 10:00:00` |
| `idempotency_key` | строка | защита от дублей при повторных запросах |
| `sync` | булево | отправить сразу и вернуть результат, а не ставить в очередь |

Ключ идемпотентности можно передать и заголовком `Idempotency-Key` — удобно, когда тело
письма собирает чужой код. Поле в теле имеет приоритет над заголовком.

У адреса есть короткий синоним `POST /api/v1/send` — тело, ответы и коды те же. Им
пользуется `bin/mailer-send` и скрипты, которым так читаемее.

### Готовое письмо целиком

Если приложение уже умеет собирать MIME (например, DokuWiki или любой другой движок со своим
почтовым классом), письмо можно отдать одним куском:

```json
{
  "raw": "MIME-Version: 1.0\r\nFrom: wiki@example.com\r\nTo: user@example.com\r\nSubject: ...\r\n\r\n...",
  "tag": "dokuwiki",
  "envelope_from": "wiki@example.com",
  "envelope_to": ["user@example.com"]
}
```

Сервис разбирает заголовки, чтобы показать письмо в панели, но отправляет байт в байт то,
что прислали. `envelope_from` и `envelope_to` необязательны — без них конверт берётся из
заголовков `From`, `To`, `Cc`, `Bcc` (сам заголовок `Bcc` из письма перед отправкой убирается).
Вместе с `raw` работают `tag`, `meta`, `transport`, `priority` и `sync`; шаблоны,
`send_at` и `idempotency_key` — нет.

Адреса принимаются в любом удобном виде:

```json
"to": "user@example.com"
"to": "Иван <ivan@example.com>, second@example.com"
"to": ["a@example.com", {"email": "b@example.com", "name": "Борис"}]
```

Вложения — файлом в base64 или путём на диске сервиса:

```json
"attachments": [
  {"name": "счёт.pdf", "content": "JVBERi0xLjQK...", "content_type": "application/pdf"},
  {"name": "логотип.png", "content": "iVBORw0KG...", "inline": true, "cid": "logo"},
  {"path": "/var/reports/2026-01.xlsx", "name": "отчёт.xlsx"}
]
```

Картинку с `"inline": true` в HTML вставляют так: `<img src="cid:logo">`.

Ответ (письмо принято в очередь):

```json
{
  "id": "c744d95c-a13c-4931-b78d-006b64007490",
  "status": "queued",
  "duplicate": false,
  "sync": false,
  "info": null
}
```

Коды ответа: `202` — принято в очередь, `200` — отправлено (при `sync`) или это повтор
с известным `idempotency_key`, `502` — при `sync` отправить не удалось.

## Статус письма

```
GET /api/v1/messages/{id}
```

`{id}` — идентификатор из ответа на отправку.

```json
{
  "message": {
    "id": "c744d95c-...",
    "status": "sent",
    "subject": "Заказ №1024 оформлен",
    "to": ["user@example.com"],
    "from": "noreply@example.com",
    "sender": "noreply@example.com",
    "tag": null,
    "attempts": 1,
    "transport": "yandex",
    "error": null,
    "created_at": "2026-01-01 10:00:00",
    "sent_at": "2026-01-01 10:00:02"
  },
  "events": [
    {"type": "accepted", "message": "Письмо принято в очередь", "at": "2026-01-01 10:00:00"},
    {"type": "sent", "message": "2.0.0 Ok: queued on ...", "at": "2026-01-01 10:00:02"}
  ]
}
```

Статусы: `queued` — ждёт отправки, `sending` — отправляется прямо сейчас, `sent` — отправлено,
`failed` — не удалось, `canceled` — отменено, `suppressed` — все получатели в стоп-листе.

## Список писем

```
GET /api/v1/messages?status=failed&search=заказ&page=1&per_page=30
```

Фильтры: `status`, `tag`, `search` (по теме, адресу, идентификатору), `date_from`, `date_to`,
`page`, `per_page`. Видны только письма своего проекта. `per_page` — от 1 до 200,
по умолчанию 30; в ответе кроме `items` приходят `page`, `pages` и `total`.

## Повтор и отмена

```
POST   /api/v1/messages/{id}/retry
DELETE /api/v1/messages/{id}
```

Повтор возвращает письмо в очередь и добавляет ему попыток. Отмена работает, пока письмо
не отправлено.

## Шаблоны

```
GET /api/v1/templates?page=1&per_page=30
```

```json
{
  "items": [
    {
      "name": "welcome",
      "description": "Приветствие нового пользователя",
      "subject": "Здравствуйте, {{ name }}!",
      "variables": ["name", "site"],
      "updated_at": "2026-01-01 10:00:00"
    }
  ],
  "total": 1
}
```

В шаблонах доступны `{{ переменная }}` (с экранированием HTML), `{{{ переменная }}}` (как есть)
и вложенные значения `{{ user.email }}`.

## Проверка сервиса

```
GET /api/v1/health
```

Ключ не нужен — адрес рассчитан на мониторинг.

```json
{
  "status": "ok",
  "time": "2026-01-01T10:00:00+03:00",
  "checks": {
    "database": {"ok": true},
    "queue": {"ok": true, "ready": 0, "delayed": 0, "failed": 0},
    "worker": {"ok": true, "last_seen": "2026-01-01 10:00:00", "seconds_ago": 3, "processed": 128}
  }
}
```

`status` бывает `ok`, `degraded` (например, молчит воркер) и `error` (недоступна база,
код ответа 503).

## Стоп-лист

Адресам из стоп-листа сервис не пишет: письмо им отсеивается на приёме. Если закрыты
все получатели, письмо принимается со статусом `suppressed` и никуда не уходит.

```
GET /api/v1/suppressions?reason=bounce&search=example.com&page=1
```

```json
{
  "items": [
    {
      "id": 12,
      "email": "ivan@example.com",
      "reason": "bounce",
      "source": "bounce",
      "project_id": null,
      "note": "550 5.1.1 user unknown",
      "expires_at": null,
      "created_at": "2026-01-01 10:00:00"
    }
  ],
  "total": 1,
  "page": 1,
  "pages": 1
}
```

Видно записи своего проекта и общие (`project_id: null`) — те, что закрыты для всех.

```
POST /api/v1/suppressions
{"email": "ivan@example.com", "reason": "unsubscribe", "note": "отписался"}
```

`reason` — `bounce`, `complaint`, `unsubscribe` или `manual` (по умолчанию). Адрес
закрывается только для вашего проекта. Ответ — `201` с созданной записью.

```
DELETE /api/v1/suppressions/ivan@example.com
```

Снимает запись своего проекта. Адрес, закрытый для всех (обычно это отказ почтового
сервера), через API не открывается — ответ `403`, снять его может администратор в панели.

## Отписка одной кнопкой

Если у проекта включена кнопка «отписаться», сервис сам добавляет письму заголовки
`List-Unsubscribe` и `List-Unsubscribe-Post` — почтовый клиент получателя покажет
кнопку рядом с отправителем. Ничего передавать в API для этого не нужно: галочка стоит
у проекта, внешний адрес — в `APP_URL`. Заголовки получает письмо с одним получателем.

Ссылка ведёт на публичный адрес сервиса:

```
GET  /unsubscribe/{токен}     страница с кнопкой
POST /unsubscribe/{токен}     собственно отписка (её же зовёт почтовый клиент)
```

Ключ проекта здесь не нужен — всё решает подпись в токене. Отписанный адрес попадает
в стоп-лист проекта с причиной `unsubscribe`, и следующее письмо ему не уйдёт.
Подробности — в `docs/OPERATIONS.md`.

## Метрики

```
GET /metrics
GET /api/v1/metrics
```

Состояние сервиса в формате Prometheus: очередь, письма по статусам, воркер, вебхуки.
Ключ проекта здесь не работает — доступ закрывает свой токен `METRICS_TOKEN`
(`Authorization: Bearer <токен>` или `?token=`). Подробности и список метрик —
в `docs/OPERATIONS.md`.

## Ошибки

```json
{
  "error": {
    "message": "Данные запроса не прошли проверку",
    "status": 422,
    "details": {
      "errors": [
        "Не указан ни один получатель (поле to)",
        "Письмо пустое: нужно указать text, html или template"
      ]
    }
  }
}
```

| Код | Когда |
|-----|-------|
| 401 | ключ не передан или неверный |
| 403 | проект отключён |
| 404 | письмо не найдено |
| 405 | неподходящий метод |
| 409 | письмо уже отправлено или отменено |
| 422 | данные не прошли проверку |
| 429 | превышен лимит проекта |
| 500 | внутренняя ошибка (подробности — в логах) |
| 502 | при `sync` отправить не удалось |

## Вебхуки

Вебхук — это подписка проекта на события его писем: адрес, секрет подписи и список
событий. Заводятся они в панели (**Вебхуки → Вебхуки проектов**, или из карточки
проекта), одному проекту можно завести сколько угодно — например, боевой приёмник на
все события и отдельный на одни отказы.

### События

| Событие | Когда |
|---------|-------|
| `message.queued` | письмо принято в очередь |
| `message.sent` | письмо ушло получателю |
| `message.failed` | попытки кончились, письмо не отправлено |
| `message.retry` | попытка не удалась, письмо вернулось в очередь |
| `message.canceled` | письмо отменено до отправки |
| `message.suppressed` | получатели закрыты стоп-листом |
| `message.bounced` | сервер получателя вернул отказ |
| `recipient.unsubscribed` | получатель нажал «отписаться» |
| `ping` | проверка связи кнопкой из панели |

Пустой список событий у подписки означает «все», включая те, что появятся позже.

### Тело запроса

Тело одинаковое у всех событий: конверт с тем, что случилось, и данными внутри.

```json
{
  "id": "9f1c3a5e-2f4b-4c1a-9d7e-3b2a1c0d4e5f",
  "event": "message.sent",
  "occurred_at": "2026-08-21T14:37:28+03:00",
  "project": { "id": 3, "name": "интернет-магазин" },
  "data": {
    "message": {
      "id": "c744d95c-...",
      "status": "sent",
      "subject": "Заказ №1024 оформлен",
      "from": "shop@example.com",
      "to": ["user@example.com"],
      "cc": [],
      "tag": "orders",
      "template": null,
      "transport": "yandex",
      "source": "api",
      "attempts": 1,
      "created_at": "2026-08-21T14:37:12+03:00",
      "sent_at": "2026-08-21T14:37:28+03:00"
    },
    "info": "2.0.0 Ok: queued on ..."
  }
}
```

`data.message` есть у всех событий про письмо. Рядом с ним лежит то, что относится к
самому событию: `error` и `attempts` у `message.failed`, `next_try_in` у `message.retry`,
`recipient` и `answer` у `message.bounced`, `recipients` у `message.suppressed`,
`email` у `recipient.unsubscribed` (письма у него нет, поэтому нет и `data.message`).

`id` — идентификатор доставки. Повтор приходит с тем же `id`, по нему и делается
идемпотентность: если такой уже обработан, второй раз обрабатывать не нужно.

### Заголовки и подпись

```
X-Mailer-Event: message.sent
X-Mailer-Delivery: 9f1c3a5e-2f4b-4c1a-9d7e-3b2a1c0d4e5f
X-Mailer-Timestamp: 1787055448
X-Mailer-Attempt: 1
X-Mailer-Signature: t=1787055448,v1=<hmac-sha256>
```

Подписывается строка «время.тело» — время входит в подпись, поэтому перехваченный
запрос нельзя переиграть позже: сверьте `t` с текущим временем и отбросьте старое.

```php
$body   = (string) file_get_contents('php://input');
$header = $_SERVER['HTTP_X_MAILER_SIGNATURE'] ?? '';

if (preg_match('/t=(\d+),v1=([0-9a-f]{64})/', $header, $m) !== 1) {
    http_response_code(403);
    exit;
}

[$all, $timestamp, $signature] = $m;

// Запрос старше пяти минут не принимаем
if (abs(time() - (int) $timestamp) > 300) {
    http_response_code(403);
    exit;
}

if (!hash_equals(hash_hmac('sha256', $timestamp . '.' . $body, $secret), $signature)) {
    http_response_code(403);
    exit;
}
```

Готовый приёмник — `integrations/php-sdk/examples/webhook-receiver.php`.

Ответ 2xx считается успехом. Иначе сервис повторит доставку с растущими интервалами
(по умолчанию до пяти раз: 30 с, 2 мин, 10 мин, 30 мин, 2 ч). Что именно ушло и что
ответил ваш сервер — видно в панели, в карточке доставки.

### Прежний формат

Подписки, заведённые до конверта, продолжают получать старое плоское тело
(`event`, `message_id`, `status`, `subject`, `to`, `tag`, `timestamp`) с прежними
именами событий `sent` и `failed` и прежней подписью `X-Mailer-Signature: sha256=<hmac
от тела>`. Формат этот застыл: событий в нём два, времени с часовым поясом нет. Новым
приёмникам он не нужен, переключается версия в форме вебхука.
